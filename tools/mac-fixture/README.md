# 私有 Mac 运行候选准备工具

这个工具从使用者自有的 iPhone App、资源档案和固定版本的上游源码，准备一份可以进一步验证的 Mac 运行候选。它会构建宿主、生成真实数据表和 MSL 着色器源码，**准备过程不执行游戏**。准备成功不代表启动、Metal 编译、联网或 G0 已通过。

当前支持 `d2r-mobile` 提交 `120fe55c02a5633476998a44f8c3c3c809fa48b0`，对应 `3.3.94012-r44`。从提供的 Git 仓库读取该提交的 `dm/` 快照，工作区里的未提交改动不会进入构建。完整宿主只存在于私有输出中，公开仓库继续保持一份上游来源。

## 输入与运行

需要 Apple Silicon Mac、macOS 26 或以上、可用的 Xcode C 编译器和 macOS SDK，以及预先准备的以下工具：

- .NET 10 SDK 的实际 `dotnet` 可执行文件。
- SPIRV-Cross 的实际 `spirv-cross` 可执行文件。
- 当前仓库构建的 `d2r-inspect`，支持 `-module main` 和 `-module sdk`。
- Python 3.11 或以上与 uv。Python 依赖通过本子项目的 `uv.lock` 安装。

准备工具不会安装系统工具。首次 .NET 调用起就关闭开发证书生成，并把 CLI、NuGet、临时文件和编译缓存限定在输出的暂存目录中。NuGet 还原使用输出中的独立配置，只连接公开 NuGet 源；它不连接官方游戏服务。

在仓库根目录运行，将尖括号中的内容替换为实际路径：

```sh
uv run --project tools/mac-fixture d2r-mac-fixture \
  --app '<已解包的 iPhone App.app>' \
  --resources '<包含 data/ 的游戏资源文件夹>' \
  --source '<含固定上游提交的 Git 仓库>' \
  --dotnet '<实际 dotnet 可执行文件>' \
  --spirv-cross '<实际 spirv-cross 可执行文件>' \
  --inspector '<当前仓库构建的 d2r-inspect>' \
  --out '<尚不存在的私有输出目录>'
```

把 `UV_CACHE_DIR`、`UV_PROJECT_ENVIRONMENT` 和需要时的 `UV_PYTHON_INSTALL_DIR` 指向仓库 `.tmp/`，即可让 uv 的环境和缓存也留在项目内。完整命令的集成入口由仓库根目录维护。

输出父目录须已存在，输出本身须不存在，且不能与任何输入目录重叠。工具在同一父目录建立独占暂存目录，全部阶段成功后使用操作系统的“不替换”重命名原子发布。并发创建的目标也会被保留。失败默认删除本次暂存内容；`--keep-failed` 可留下日志和中间数据供调查。每个外部阶段的时间上限由 `--stage-timeout-minutes` 设置，默认 30 分钟；`--jobs` 设置着色器并发数，默认 4。

## 生成内容与证据边界

准备流程会完成以下工作：

1. 先把 main、sdk 的 fixups 和 gates 一次性复制到私有输入快照，再用现有 Go 检查器读取同一份 fixups 快照，分别校验和重建两个模块。字节不变地复制为宿主需要的 `.patched.bin`，从同一份快照复制运行元数据，逐一核对检查器的 fixups 身份与全部运行文件的大小、哈希；不会伪造原始 NSO。
2. 验证 App 覆盖层中的 TVFS/BLTE 索引和存储校验，恢复带类型的文件索引。文件表大小、CFT 内容大小、编码字符串表字节偏移分别保留。
3. 从真实内容计算校验值，为未修改的上游数据表生成器提供明确标注的索引子集适配层。原提取工具的 FileId、Flags 和不存在的资源不会被冒充为已恢复内容。
4. 运行未修改的上游生成器，生成三个真实宿主头文件；恢复着色器包及 main 中的内嵌着色器，并核对内嵌控制段键。
5. 编译上游 .NET 翻译器，以上游支持的 nometal 路径生成完整 MSL 源码，登记实际工具指纹和独立的着色器链。缓存中的 `.metallib` 扩展名沿用上游约定，其内容明确记录为源码，不声称是已编译的 Metal 库。
6. 从实际 MSL 重新运行 `c1_guard.py`，把匹配当前链的 C1 元数据、原始着色器映射和管线预热清单放在一起；随后构建带 `DM_SHELL` 的 Mac 宿主。

`manifest.json`、各阶段日志和回执记录输入、工具、源码快照、模块、资源、着色器和宿主身份。私有源码快照里允许变化的配置只有实际工具指纹锁和生成的链头；不会静默修改上游实现。

资源通过只读引用供生成器使用。工具不写 App、游戏档案或提供的 Git 工作区；资源档案、原始 fixups/gates、私有元数据快照和全部运行模块文件会在发布前再次核对身份。输入在准备过程中改变会使准备失败。**输出仍依赖原 App 和资源路径的生命周期**：不能移动、删除或修改这些输入后继续把候选视为同一份已检查输入。这个工具不负责为游戏进程建立只读沙箱，也没有启动游戏的命令。

部分语言语音档案可能不在手机精简资源中。索引会保留这些引用并报告缺失；实际生成阶段需要的内容缺失时直接失败。成功不能证明完整原始资源集合已经恢复。

## 验证

```sh
uv run --project tools/mac-fixture python -m unittest discover -s tools/mac-fixture/tests
```

测试只使用合成数据，覆盖真实大小差异、编码偏移、损坏索引、BLTE 校验、解压边界、路径隔离、并发发布冲突、外部阶段失败和超时清理，以及检查器返回时外部模块元数据被修改、gates 身份和检查器快照身份不一致等情况。公开 CI 不需要游戏程序或玩家存档。
