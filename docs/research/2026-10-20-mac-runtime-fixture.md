# Mac 运行候选准备与单机执行基线

日期：2026-10-20。范围：macOS / ARM64、完整游戏客户端、单人本地世界。**这不是 Linux 房间工作进程资格记录，G0–G5 均未通过。**

本报告承接 [G0 静态传输边界](2026-10-20-g0-transport-boundaries.md)。该报告中的源码、Hopper/Ghidra、队列及长度结论保持有效；本报告另行记录实际的 Mac 构建、资源准备、进入世界和保存退出证据。后续[原生观察报告](2026-10-20-native-transport-probe.md)固定另一份观察二进制并记录 213 tick 与逐通道消息对照；本报告保留历史基线 159 tick，不合并不同宿主的结果。产品仍报告 `game_worker: "unavailable"`、`multiplayer_available: false`，`/readyz` 返回 503。

## 本次交付与证明范围

公开的 [`tools/mac-fixture`](../../tools/mac-fixture/README.md) 从自有输入和固定源码生成私人运行候选，公开仓库不复制完整上游宿主。工具本身只准备，不执行游戏。最终候选另由独立、有范围限制的私人执行流程运行，得到本地世界推进到 tick 159、保存退出返回菜单和进程退出码 0 的记录。

准备阶段和执行阶段使用不同的清单。准备清单的 `prepared_unexecuted` 准确描述工具完成时的状态；后续执行记录引用其哈希，不回写或篡改原始准备证明。普通源码测试、真实输入准备成功、实际进入世界也分别记录，不能互相替代。

| 验证层 | 已取得的结果 | 不能据此认定 |
|---|---|---|
| Go 静态检查 | `main` / `sdk` 两模块逐节重建与身份清单；`make check` 通过。 | 两模块字节本身可独立执行。 |
| Python 合成测试 | `make fixture-test` 使用锁定依赖与 Python 3.12，17 项测试通过。 | 自有游戏资源、GPU 和设备已经由公共 CI 测试。 |
| 真实输入准备 | 全部 15 阶段通过，真实头文件、着色器源码、元数据和 Mac 宿主生成成功。 | 准备工具执行了游戏或通过 G0。 |
| 私人 Mac 执行 | 最终公开工具生成的候选进入本地世界，159 tick 后保存退出，返回菜单，进程退出码 0。 | Linux、无 GPU 服务端、双进程桥接、远程入场或四人联机通过。 |

## 资源与真实生成器

从 App 的 TVFS/BLTE 覆盖层恢复了含 **133,200 条路径**的索引，并保留文件大小、CFT 内容大小和编码字符串表字节偏移的区别。路径存在不代表内容档案齐备：手机精简资源缺少部分语言语音档案，这些引用被报告保留，没有伪造内容。

## 着色器、运行元数据与构建

工具构建固定上游的 .NET 翻译器，使用上游支持的 nometal 路径生成 MSL 源码，核对 main 内嵌着色器控制键并登记实际工具指纹。共处理 **6,927 个着色器键**，缓存有 **7,212 个沿用 `.metallib` 扩展名的条目**；这些条目是翻译后的源码，不以 `MTLB` 开头，不是预编译 Metal 库。真实 GPU 编译及场景可用性只能由执行阶段证明，单机场景成功也不证明所有着色器变体均可用。

C1 元数据按实际 MSL 与当前链重新生成，并与 `shader_map.tsv`、管线预热清单一起记录摘要。不能用其他链的旧元数据替代。最终候选的着色器链为 `25119b57670f`。

准备工具先一次性快照 main/sdk 的四份 fixups/gates，再让检查器和运行文件使用同一快照。发布前重新核对源输入、四份快照与六份运行文件（两份模块字节和四份元数据）的身份。发现检查后外部元数据变化即失败，避免把先前检查的 fixups 身份与后来复制的 gates/fixups 混合发布。此问题已经修复并由独立审查复核，相关变化和检查器身份不一致均有合成测试。

私有源码中只允许工具指纹锁和生成的着色器链配置变化；完整源码、数据、生成头文件和宿主留在私人输出。工具不安装系统依赖，.NET、NuGet、编译缓存及临时文件定向至候选暂存目录，并从首次 .NET 调用开始关闭开发证书生成。

## 最终候选的实际执行

以下身份对应**最终公开准备工具产生的候选**，不能与早期私人宿主或其他构建混用：

| 身份 | 值 |
|---|---|

| Mac 宿主 SHA-256 | `b15bbc0bfbe7e63a6368c3988258f1844fa216d7a512b5e63d6fde3516beb9a4` |

执行使用独立工作目录和受操作系统约束的进程沙箱：宿主网络被拒绝，原始 App、资源、模块及参考存档只读；宿主在用户主目录内的写入限制到本仓库的 `.tmp`，临时目录和存档输出也显式指向本次私人实验目录。该进程级验证不声称约束整个系统或系统管理的 Metal 编译服务缓存。从已有备份复制 24 个文件形成测试副本，原始备份保持不变。准备工具自身不建立这套执行沙箱；这些约束属于另行记录的运行实验。

实际记录如下：

1. 导航进入本地角色世界，记录 `ToGame`，完成加载；私人 1600×900 画面显示鲁高因场景。
2. 记录 160 条 tick 样本，最大 tick 为 **159**；随后通过游戏暂停菜单的保存退出路径发出 `ExitGame`。
3. `ExitGame` 后观察到 **3 次实际保存提交**，输出角色文件发生变化，随后记录 `ToFrontEnd` 和主菜单重新打开。
4. 达到保存退出目标后以 SIGTERM 关闭所属进程，退出码为 **0**；实验耗时 20.57 秒。原始备份摘要复核不变。

这证明此固定候选在 Mac 完整客户端中执行过单人世界与正常保存退出。它不证明服务端房间准入、双进程透传、多人归属、崩溃恢复、断电持久化或全世界玩法覆盖。保存提交日志与文件变化只能支持观察到的正常路径，不能替代跨玩家一致检查点与故障矩阵。

## 历史失败、修复与证据位置

最初的探测启用了不适用于菜单空闲阶段的游戏进展监视，进程以 142 退出。后续按 UI 里程碑核对，区分正常菜单空闲与游戏逻辑停滞；该状态不能被笼统称为无法启动或图形失败。另有真实的 C1 元数据匹配问题：旧相邻列表头声明 `b-15cf7ca29eaf`，实际早期宿主链为 `b-fced7db3cb3d`，加载器因此明确退回全 C1 路径。使用未修改的 `c1_guard.py` 扫描全部 6,927 个实际 MSL，得到 170 个键，与固定源码及签名 App 的列表一致；在新的私人目录生成匹配当前链的元数据，保留未改动的 shader map 与预热清单。最终公开工具自动生成匹配链 `25119b57670f` 的元数据并核对摘要。此修复与监视器对菜单空闲的误判分别记录。

早期私人宿主 SHA-256 为 `3bc1efba392628f61877bbfbf2129d03419bdac3cd9179951d806b58e58bcce5`，也有进入世界 157 tick 及返回菜单的历史记录。本报告的执行结论优先使用最终公开候选的 159 tick 记录，不把不同宿主或着色器链的日志合并为一份结果。

私人清单与原始日志保存在：

- `.tmp/mac-fixture/prepared-public-metadata-smoke/manifest.json`：最终候选的 15 阶段、模块、资源、工具和构建来源。
- `.tmp/mac-fixture/metadata-prep-qualification.json`：四份元数据快照及六份运行文件核对。
- `.tmp/experiments/g0-boot-qualification/latest-public-world-run.json` 及其关联运行目录的 `world-qualification.json`：最终候选实际执行、UI 事件、tick、退出及保存断言。
- `.tmp/experiments/g0-runtime-fixture-research/`：资源、生成器、着色器及早期私人构建来源；`qualified-metadata/fced7db3cb3d/` 保留 C1 资格与启动说明，历史记录保持原样。
- `.tmp/reviews/mac-fixture-tooling-review.md`：独立审查及元数据修复复核。

玩家名称、设置、存档内容、源档案、完整路径、原始截图、原始反编译和运行载荷均保持私人材料。公开文档只记录必要身份、统计及通过范围。
