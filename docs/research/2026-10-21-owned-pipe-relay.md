# 真实游戏与所属转运进程的数据闭环

日期：2026-10-21。已在一个真实 Mac 游戏世界与一个所属 Go 子进程之间完成字节转运、移动及正常保存退出。**这不是两个游戏客户端共享世界；G0–G5、Linux 游戏工作进程和四人联机仍未通过。** 历史首次断开继续保持未确定原因。

本报告承接[生命周期观察](2026-10-21-lifecycle-observation.md)。本次从观察推进到主动替换有效本地发送的数据范围，限定于已验证的 mode 1。构建及执行仍分别管理：准备工具不执行游戏，实际执行使用独立私有输入副本、网络拒绝、文件写入边界和所属进程监督。

## 实现与所有权

新增 `internal/piperelay`、`cmd/d2r-relay` 及原生管道接口。原生先将发送范围复制进私有观察文件，再把该自有副本送入子进程。子进程完整缓冲后回送；父进程核对头和每个字节，将**实际回送的独立范围**传给原方法，而非核对后继续使用原范围。

每次调用拥有各自的回送数据和描述符，保留至原方法完成后、在途令牌释放前。嵌套调用不共享缓冲或持有跨原方法的锁。固定本地 C2S 队列及 S2C 部分缓冲、重入和回调路径会复制保留的数据；这个结论不能推广到未验证异步模式。原始六处出队和接收/重试流程不变。

空 C2S 在主动模式下明确失败，因为原入队方法会读取首字节；空 S2C 可转运零字节后使用原空描述符。长度上限是实验资源边界，不是引擎接受任意网络输入的保证。失败或数据不等时不把未验证内容交给游戏。

内部 ABI 状态增加每次调用的所有权字段，状态 256 字节、栈帧 272 字节，仍保持整数/向量、NZCV、原 x8 结果及 16 字节栈对齐。原生模式必须显式为 observe 或 relay；后者需要两个已继承且读写方向正确的管道端点。不存在自动退回本地转运的选择。

格式和严格期限见[管道契约](../../native/transport-probe/relay.md)。`D2RRP001` 的 C2S 类型 1、S2C 类型 2 与传输观察类别相反，需要显式映射。子进程报告只证明 Close/请求 EOF 的完整输入；原生还核对 Ack/响应 EOF，监督方另行回收子进程并要求退出 0。

## 测试与剩余条件

`make check` 通过，核心覆盖率 93.5%，管道包 100%，转运 CLI 87.1%；24 项 Python 合成测试通过。原生跨语言测试使用实际 Go 子进程，覆盖真实回送指针、嵌套缓冲存活、1 MiB 大于管道容量的数据、空消息区别、断管、头/数据损坏、单一绝对期限、错误 Ack 和额外响应字节；ASan/UBSan 通过。独立审查无未解决 critical/major。镜像和远程 CI 按对应分支实际结果核对。

该实验只涵盖有效本地发送范围，不能证明全部流量、通用 S2C 帧边界、跨队列全局顺序或角色生命周期完整性。子进程没有原游戏、第二个玩家或权威状态。`owned_pipe_roundtrip_qualified` 与 `two_guest_transport_qualified` 分别记录，不能借此把 G0 或联机声明变成 true。
