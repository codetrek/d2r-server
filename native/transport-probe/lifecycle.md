# 生命周期状态观察文件

这是固定 Darwin ARM64 私人实验的 `D2RLC001` / 版本 1 状态格式。它与传输 trace v2 分开保存，记录两个既有观察门在**宿主回调之前和之后**的原始状态。观察门位于原程序入口，回调返回不代表原程序完整 tick 或 UI 总线函数已返回。

`D2R_LIFECYCLE_TRACE` 必须指定新的绝对路径，文件排他创建为 0600。容量固定为 `256 + 160 × 16384 = 2621696` 字节，最多 16,384 条记录。容量限制不构成 CPU 开销上限。文件包含原始状态和时钟值，保留在私人实验目录；紧凑 JSON 不输出无限记录、Guest 指针、消息载荷或面板字符串。

## 集成与关闭

构建分别编译两个未修改的上游源文件：只有 `main.c` 使用初始化包装宏，只有 `hle.c` 使用 `gate_obs_set=d2r_upstream_gate_obs_set`。其余编译单元保留原始名字和参数。符号检查要求真实初始化、包装器、真实注册函数、注册包装器及六个传输垫片各有唯一定义。

注册包装器保持上游的“最后一次注册生效”约定。初始化前处于 DORMANT，只记录回调关系并转调；不读取 Guest、帧号或状态文件。UI 门 1 和 tick 门 2 使用各自分派函数，其他编号交还原注册函数验证。NULL 真正取消注册；已取得旧分派地址的调用遇到 NULL 时也不调用已撤销回调。

每次分派在入口保存当前主回调，记录前状态，调用该主回调一次，再记录后状态。主回调收到同一寄存器数组地址，其寄存器修改和 errno 结果保留。嵌套调用独立准入，持锁期间不调用主回调；回调中请求同步关闭会明确失败，不等待自己。

固定模块字段只在已验证的安装线程读取。动态父对象 `+0x58` 和借用 UI 消息的 24 字节通过内核复制到自有局部变量，失败明确记录；这不证明动态对象身份或完整所有权。外来线程只增加缺口计数，始终转调原回调，不能调用安装线程的帧号读取器或读取 Guest。

与传输观察共用一个起初不存在的 `D2R_PROBE_STOP_PATH`。两份文件创建之后、发布观察钩子之前再次检查停止路径仍不存在，防止 `..` 或父目录符号链接使捕获文件本身成为停止标记。控制线程先结束传输采样准入并等待在途方法，然后结束生命周期准入并等待完整主回调和后状态复制。两份文件各自同步关闭；生命周期 I/O 失败会使传输出现缺口，并禁止发布传输 CLOSED。采样关闭不排空原程序消息队列或未来 IPC。

## 文件头：256 字节

所有整数小端。

| 偏移 | 类型 | 内容 |
|---:|---|---|
| 0 | 8 字节 | `D2RLC001` |
| 8 / 12 | u32 / u32 | 版本 1 / 文件头 256 |
| 16 / 24 | u64 / u64 | 容量 2621696 / 已提交前缀末端 |
| 32 / 40 | u64 / u64 | 已记录快照数 / 准入的主回调次数 |
| 48 / 56 / 64 | u64 | 错误 / 超出快照容量 / 外来线程次数 |
| 72 | u64 | 位 1 已开始、2 画像已核对、4 窗口 CLOSED、8 存在缺口 |
| 80 / 88 | u64 / u64 | 安装线程编号 / 记录长度 160 |
| 96 / 104 | u64 / u64 | 宿主单调时钟开始 / 结束纳秒值 |
| 112 / 144 | 各 32 字节 | main / sdk 文件 SHA-256 |
| 176 | 80 字节 | 保留，零 |

只读取已提交前缀中的完整记录。结束后的稳定快照或已结束所属进程是读取前提。`_exit` 不会补齐未完成回调或 CLOSED。画像标志、计数和关闭信息均属于该份观察文件，不能替代独立的候选身份及运行回执。

## 快照：160 字节

| 偏移 | 类型 | 内容及固定来源 |
|---:|---|---|
| 0 / 8 / 16 / 24 | u64 | 连续序号 / 宿主帧号 / 宿主单调纳秒 / 传输已记录序号快照 |
| 32 / 36 | u32 / u32 | 门编号 1 或 2 / 阶段 0 回调前、1 回调后 |
| 40 / 48 | u64 / u64 | UI 类别与动作哈希；不适用或读取失败时为零并由标志区分 |
| 56 | u32 | 字段有效性标志，见下文 |
| 60 | u32 | main `+0x2d20b8c` 操作模式 |
| 64 / 68 / 72 / 76 | u32 | main `+0x2d20b90/b94/b98/b9c` 原始状态 |
| 80 / 84 | u32 / u32 | main `+0x2d20e7c` 时钟值 / `+0x2d20e80` 存储的错误编号 |
| 88 / 92 | u32 / u32 | main `+0x2d2d1f0/1f4` 原始前端计时值 |
| 96 / 100 | u32 / u32 | main `+0x2d435d0` 延后消息计数 / 客户端对象 `+0x14` 模式 |
| 104 / 112 | u64 / u64 | 客户端 `+0x28/+0x30` 接收/发送时间原值 |
| 120 / 124 | u32 / u32 | main `+0x2d20b80` 所指对象 `+0x58` 的原始值 / 保留零 |
| 128 | u64 | main `+0x2d20fc0` 待处理错误截止时间原值 |
| 136 / 137 / 138 | u8 | main `+0x2d20ba1`、`+0x2d2d1ec`、客户端 `+0x2f0` 的布尔状态 |
| 139 / 140 / 141 | u8 | 客户端 `+0x18/+0x20/+0x50` 是否非零，不保存原指针或不明数值 |
| 142 | 18 字节 | 保留，零 |

标志：1 UI 元数据有效、2 UI 元数据读取失败、4 父对象指针非零、8 父对象字段读取有效、16 父对象字段读取失败。UI 记录必须标明 1 或 2，tick 不能携带 UI 标志；父对象状态只能是不存在、4|8 或 4|16。不存在和读取失败是不同状态；失败字段的零值不具有效字段的含义，并使观察不合格。

时间字段保持原始无符号表示。宿主 CLOCK_MONOTONIC 与 Guest 时钟不能直接相减；低 32 位计时也不能忽略回绕。此格式不进行时钟转换或调用新的 Guest 辅助函数。

`+0x2d20ba1` 是共享生命周期状态，单凭它不能宣布发生错误。待处理错误截止时间 `+0x2d20fc0` 非零才表明此处已有待处理错误；存储编号也可能在之后保留旧值。正常生产路径中，错误 8/30 与 7/28 的本地化文本不同，多个编号共享文本，截图无法独立恢复唯一编号。

## 读取与证明范围

```sh
./bin/d2r-trace -format lifecycle -input .tmp/owned-run/lifecycle.trace \
  -report .tmp/owned-run/new-lifecycle-report.json
```

`internal/lifecycletrace` 检查版本、固定大小与摘要、前缀、连续序号、字段标志、保留区、回调嵌套、单调时间及传输序号和本机计数。闭合窗口满足 `记录数 + 容量溢出数 = 2 × (准入回调数 − 外来线程数)`；有缺口、未关闭、溢出或未完成嵌套时不合格。计数不是游戏 tick 数。

JSON 只给出两个门的计数、最大/剩余嵌套深度、最多 32 种原始错误编号的快照计数、溢出统计及首个待处理错误的有限上下文。原始编号计数不是错误发生次数。首个待处理错误由非零截止时间判断，不能靠共享状态字节或过往编号推断。

解析损坏和完整性不合格退出 1。完整性通过不证明导致历史断开的分支，不证明原程序完整生命周期、CPU 透明性、双进程、Linux 或多人资格。两份文件的关联由所属实验回执中的路径和哈希证明；同一模块摘要或相似序号不足以把任意两个文件拼成一次运行。
