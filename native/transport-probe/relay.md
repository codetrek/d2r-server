# 所属管道转运实验

这个构建可显式选择 `D2R_PROBE_MODE=observe` 或 `relay`。observe 维持六处传输与两个宿主回调的观察；relay 在有效本地 mode 1 发送时，把已复制的字节交给一个所属转运进程，核对回送的头和每一个字节，再把实际回送的自有范围传给原发送方法。

这是一个游戏世界加一个转运进程的字节通路实验。它不建立第二个客户端、远程房间、认证或网络服务，也不证明单一权威的多人行为。原始游戏输入、资源和参考角色保持只读，运行只使用新副本；原生 I/O 或数据核对失败会让本次实验失败，不能将未验证回送传给游戏。

## 输入与原方法语义

relay 必须提供两个已继承、彼此独立的管道端点：`D2R_RELAY_READ_FD` 是响应读端，`D2R_RELAY_WRITE_FD` 是请求写端，均须大于等于 3。类型和读写方向由系统核对；文件、套接字、标准输入输出和缺失/无效值被拒绝。observe 模式不能携带这两个参数。参数不会由构建工具继承或推测，工具也不启动转运进程。

管道使用非阻塞 I/O 和每次事务一个 2 秒的宿主单调绝对期限，覆盖全部头、数据、回送及核对，不按短读短写重新计时。只为所属写端抑制 SIGPIPE，EPIPE 仍作为错误返回；使用 Darwin `F_SETNOSIGPIPE`，不修改原程序全局信号策略。此限制是实验失败条件，不改变游戏自身期限。

观察器首先把原范围复制到有界私有传输文件，再将该副本写入管道。非空回送存储和 `{begin,end}` 描述符归每次调用独立所有，跨越完整原方法调用；在途令牌释放前回收。原方法期间可以嵌套发送，不持有跨原方法的事务锁。原调用的参数/返回寄存器及 `x8` 结果约定仍由垫片保存；内部 ABI 状态为 256 字节、完整栈帧为 272 字节，保持 16 字节对齐。只有已恢复的六个无栈参数边界使用该垫片。

固定 mode 1 的 C2S 入队、S2C 的部分缓冲和重入路径都会复制保留的消息，发送返回不携带输入范围视图；这个所有权约定不能推广到 mode 3 异步后台。阻塞转运之后会再次检查有效模式/关闭状态。有效的实际调用仍由原方法处理一次；出队不被改写，原借用队列的生命周期不变。

原本忽略的发送保留既有行为，未覆盖分支仍使观察不合格。空 C2S 不满足原入队方法读取首字节的条件，主动转运时在原调用前失败。空 S2C 可以转运零字节，随后使用原空描述符，不创建 malloc(0) 范围。表示层允许空数据不代表原引擎接受所有空消息。

## 帧：32 字节头及不透明数据

所有整数小端；不解析、拆分或合并游戏操作码。方向编码与传输观察文件不同，必须显式映射。

| 偏移 | 类型 | 内容 |
|---:|---|---|
| 0 | 8 字节 | `D2RRP001` |
| 8 | u32 | 版本 1 |
| 12 / 14 | u16 / u16 | 类型 / 保留零 |
| 16 | u64 | 从 1 开始连续递增的转运序号，与观察序号分开 |
| 24 / 28 | u32 / u32 | 连接编号 / 数据长度 |

类型 1=C2S、2=S2C、3=Close、4=Ack。观察中的 `client_send_attempt` 类别 2 映射为转运 C2S 类型 1；观察中的 `server_send_attempt` 类别 1 映射为转运 S2C 类型 2。Close/Ack 的连接号和长度必须为零。数据帧表示允许任意 u32 编号，但当前原生本地实验只转运编号 0；表示并不认证或分配连接。

单帧最多 1 MiB 数据，一个窗口最多 65,536 个数据帧、合计最多 64 MiB 数据。这些是实验内存/工作量上限，不是引擎安全长度、实际网络协议限制或生产队列配置。长度、版本、保留位、类型、顺序、截断和尾随数据均须符合各自约定，错误不得默认为兼容数据。

所属 Go 子进程完整读取有界头和数据后，才回送同一帧。不能边读请求边写回送，否则大于管道容量的请求可能与父进程相互等待。输入字节只进入独立私有记录的计数与摘要，不进入终端或无限报告。

## 结束与回执

停止标记先结束新传输准入，等待已准入的原方法、回送存储和生命周期回调完成。控制线程随后写 Close 并关闭请求写端；子进程必须读到 EOF，拒绝 Close 后的任何字节，写入并关闭排他创建的 0600 JSON 报告，最后回送 Ack 并退出。

原生控制方核对 Ack 和响应 EOF，拒绝额外响应字节，之后才允许传输 CLOSED。失败会产生缺口并禁止 CLOSED。采样窗口外仍沿既有观察器原样转调语义，不属于这次转运证明；这不是生产联网时的处理方式。

启动监督方还必须回收所属子进程，核对其退出码 0 和报告、两份捕获的来源与哈希。仅看到 Ack、EOF 或单份捕获 CLOSED 不能替代这些条件。子进程报告中的 `input_complete` 只表示输入 Close/EOF 已完成，不宣称原生方收到了 Ack。

报告给出全局及两个方向的帧数、数据字节数，以及精确的“32 字节数据头 + 全部数据”的 SHA-256。Close/Ack 不进入数据摘要。监督方应从实际传输观察中选取有效发送、重新映射方向和连续转运序号，逐个范围核对摘要及原游戏实际出队；不能只比较总字节数。

所有准备构建均不执行游戏。真实执行需单独的网络拒绝、输入只读、所属进程期限和清理回执。合成跨语言测试及真实字节转运都不能替代两客户端共享世界、四人角色归属、Linux 原游戏启动或 G0–G5。
